# A05 · Multihoming BGP

Decidir por cuál salida BGP circula cada prefijo y estudiar fallas de proveedor.

## Variante implementada

Topología fija: 6 equipos y 6 enlaces. Recursos EVE: 5 vCPU y 3080 MiB; GNS3: 6 vCPU y 5152 MiB; se exige 1024 MiB de margen adicional y disco libre antes de crear.

```text
   [isp01]                                                     [isp02]
      |                                                           |
      |                                                           |
  [edge01]----------------------------------------------------[edge02]
          \\\\\\\                                      ///////
                 \\\\\\\                      /////////
                        \\\\\\\        ///////
                               [sw01]\\\\\\
                                           \\\\\\\\\\\\\\\
                                                          \\\\\\[h01]
```

## Preparación y ejercicio

**Preparación automática:** Dos proveedores, dos bordes, iBGP/eBGP y LAN con HSRP preparados.

**Ejercicio:** Preferir ISP01 con local-preference y comprobar cambio de salida en los routers de borde.

Práctica aplica la base y comprueba su estado; referencia aplica también la solución y exige que las comprobaciones del ejercicio pasen.

## Direccionamiento y conexiones

Pools predeterminados: tránsito `10.240.0.0/16` dividido en /30; loopbacks `10.241.0.0/16` asignadas como /32; LAN `10.242.0.0/16` dividida en /24. El asistente propone un pool de loopbacks /24, suficiente para estas variantes. Son editables, privados y no se superponen.

```text
edge01 GigabitEthernet0/1 -- isp01 GigabitEthernet0/1
  10.240.0.0/30
edge02 GigabitEthernet0/1 -- isp02 GigabitEthernet0/1
  10.240.0.4/30
edge01 GigabitEthernet0/2 -- edge02 GigabitEthernet0/2
  10.240.0.8/30
edge01 GigabitEthernet0/3 -- sw01 GigabitEthernet0/0
edge02 GigabitEthernet0/3 -- sw01 GigabitEthernet0/1
h01 eth0 -- sw01 GigabitEthernet0/2

DIRECCIONES
isp01: GigabitEthernet0/1 10.240.0.2/30, Loopback0 10.241.0.1/32, Loopback10 10.244.0.1/32
isp02: GigabitEthernet0/1 10.240.0.6/30, Loopback0 10.241.0.2/32, Loopback10 10.244.0.1/32
edge01: GigabitEthernet0/1 10.240.0.1/30, GigabitEthernet0/2 10.240.0.9/30, GigabitEthernet0/3 10.242.0.2/24, Loopback0 10.241.0.3/32
edge02: GigabitEthernet0/1 10.240.0.5/30, GigabitEthernet0/2 10.240.0.10/30, GigabitEthernet0/3 10.242.0.3/24, Loopback0 10.241.0.4/32
h01: eth0 10.242.0.10/24
```

VLAN, áreas, ASN, identificadores VRF y VNI son valores definidos por la receta; se incluyen en la configuración exportada. IPv6 utiliza el prefijo de laboratorio `fd42:4e4c:4600::/48`. No se reservan direcciones fuera de esta maqueta aislada.

## Límites

La cantidad de equipos y la estructura son las de esta variante. No incluye todas las variantes pedagógicas posibles del escenario. Las pruebas son funcionales; no miden rendimiento ni tiempo de convergencia.

EVE: laboratorio nuevo en la carpeta elegida, tenant admin 0, sin enlaces externos. No se sobrescriben laboratorios. Una falla conserva el registro y los recursos creados para inspección; no se reintenta automáticamente.

GNS3: proyecto nuevo mediante el perfil 3.0.6 Nexo; acceso SSH directo o sesión temporal de Proxmox. No agrega enlaces externos ni instala imágenes. Si falta una imagen o su BIOS, la creación se detiene antes de crear recursos.

La preparación completa, la solución y las pruebas se exportan con `nlf plan A05 --name ejemplo-a05 --mode reference --output build/ejemplo-a05`.
